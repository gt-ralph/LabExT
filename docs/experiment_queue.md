# Loading and Saving an Experiment Queue

LabExT can execute a queue of experiments that was written outside the GUI - typically generated by a
Jupyter notebook - and loaded via **File → Load Experiment Queue...**. The current queue can be written
back out with **File → Save Experiment Queue...**, which produces a file of exactly the same format.

Unlike the Experiment Wizard, where stage movement and Search for Peak are global checkboxes applied
before *every* measurement, a loaded queue contains **explicit alignment steps**. This lets you align
once and then run several measurements at that one alignment, which is the normal case when a fibre
array stays parked while an optical switch re-routes between output channels.

## File format

```json
{
  "labext_queue_version": 1,
  "chip_name": "MyChip",
  "entries": [
    {"type": "move", "device_id": "1042"},
    {"type": "sfp"},
    {"type": "meas", "device_id": "1042", "measurement": "LUNA_sweep_Cband_switch",
     "parameters": {"center wavelength": 1550.0, "Switch Port: M = 4": 5}},
    {"type": "meas", "device_id": "1043", "measurement": "LUNA_sweep_Cband_switch",
     "parameters": {"Switch Port: M = 4": 6}}
  ]
}
```

### Entry types

| `type` | Meaning | Keys |
| --- | --- | --- |
| `move` | Move the stages to a device | `device_id` (required) |
| `sfp` | Run a Search for Peak at the current position | `device_id` (optional, only used to refine the calibration) |
| `meas` | Run a measurement | `device_id`, `measurement`, optional `parameters`, optional `instruments`, optional `auto_align` |

`measurement` is the **measurement class name** (e.g. `LUNA_sweep_Cband_switch`), as listed in the
Experiment Wizard. `parameters` is a flat `{name: value}` map; any parameter you omit keeps the
measurement's default. Parameter names must match the measurement exactly - an unknown name is
rejected at load time rather than silently ignored.

`instruments` is optional. When omitted, the measurement reuses the instrument selection you last made
for it in the Experiment Wizard, so select instruments there once before loading a queue.

`auto_align` is optional and defaults to `false`, which is what a hand- or notebook-written queue wants:
such a queue carries its own explicit alignment steps, and the global "auto move stages" / "execute
Search for Peak" checkboxes must not align a second time. It exists so that a queue saved out of the
GUI, whose entries *do* align themselves, round-trips instead of silently losing that. A file written
with `"auto_align": true` and opened by an older LabExT loses the flag.

## Validation: same input location per block

The queue is split into **blocks** at every `move`/`sfp` entry, and at every measurement with
`auto_align` set - such a measurement aligns itself, which is an alignment step like any other, just
not a separate queue entry. Within one block - i.e. between two
alignment steps - every measurement must target a device at the **same input location**
(`Device.in_position`, to within 1.0 um, see `INPUT_LOCATION_TOLERANCE_UM` in
`LabExT/Experiments/QueueValidation.py`).

This deliberately allows *different* devices in one block, as long as they share an input location -
exactly the case where one input coupler feeds several devices read out on different fibre-array
channels. What it prevents is a measurement on a device whose input sits somewhere else, which would
run misaligned because nothing moved the stages there.

Loading is all-or-nothing: if validation fails, LabExT reports every problem and appends nothing.

## Writing a queue from a notebook

No library is needed - the entries are plain dicts:

```python
import json

def move(device_id):                 return {"type": "move", "device_id": str(device_id)}
def sfp():                           return {"type": "sfp"}
def meas(device_id, cls, **params):  return {"type": "meas", "device_id": str(device_id),
                                             "measurement": cls, "parameters": params}

queue = {"labext_queue_version": 1, "chip_name": "MyChip",
         "entries": [move(1042), sfp(),
                     meas(1042, "LUNA_sweep_Cband_switch", **{"Switch Port: M = 4": 5}),
                     meas(1043, "LUNA_sweep_Cband_switch", **{"Switch Port: M = 4": 6})]}

with open("my_queue.json", "w") as f:
    json.dump(queue, f, indent=2)
```

Ready-to-adapt notebooks for C-band Luna OVA measurements live in `queue_notebooks/`.

## Running a loaded queue

Press **Run (F5)** as usual - a loaded queue executes through the same engine as any other ToDo
list. How the "Execute ToDos" checkboxes apply:

| Control | Effect on a loaded queue |
| --- | --- |
| Pause after every measurement (Manual Mode) | **Applies.** Pauses after each *measurement*; move/sfp steps never pause, so one Run does `move → sfp → measurement → pause`. Uncheck it to run the whole queue unattended. |
| Seconds to wait between measurements | Applies after measurements only, not after alignment steps. |
| Automatically move Piezo Stages to device | **Ignored** for entries with `auto_align` false, which is every notebook-written entry - the queue's own `move` steps do this. Applies to entries saved from the GUI with `auto_align` true. |
| Execute Search-for-Peak before measurement | **Ignored** for entries with `auto_align` false - the queue's own `sfp` steps do this. Leave it off unless the queue contains GUI-saved entries. |
| Refine stage calibration from Search-for-Peak results | **Applies** to the queue's `sfp` steps. |

There is deliberately no separate "queue mode": whether an entry aligns itself is a property of the
entry, not a global switch, so wizard-created ToDos and loaded queue entries can sit in one list and
each still behave correctly.

## Execution notes

- Alignment steps produce no measurement record. A queued Search for Peak writes its own
  `<chip>_sfp_<timestamp>.json` result file **and** is copied into the `search for peak` field of every
  measurement that follows it, until the next `move` invalidates that alignment.
- Queue entries default to `auto_align=False`, so the global "auto move stages"/"execute search for
  peak" checkboxes never align a second time for them. Those checkboxes keep working as before for
  ToDos created through the Experiment Wizard, and the two kinds can coexist in one queue.

## Saving the current queue

**File → Save Experiment Queue...** writes whatever is in the ToDo list to a queue file. The intended
use is surviving a restart: LabExT only reloads instrument and measurement modules at startup, so any
driver change during a session costs the queue unless it is saved first. Save, restart, then load the
file back with **File → Load Experiment Queue...**.

Both kinds of entry can be saved - ones loaded from a queue file and ones built through the
measurement wizards - and `auto_align` is preserved either way, so a saved wizard ToDo still aligns
itself when reloaded.

Saving is all-or-nothing and validates first, so LabExT will not write a file that its own loader
would refuse. Two things worth knowing:

- **Sweeps are flattened.** The file format has no way to express a sweep group, so each member is
  saved as an independent measurement. Reloading gives the same measurements with the same settings,
  but no shared sweep summary file and no common results subfolder. You are warned when this happens.
- **Instrument selections are saved verbatim, including any login details** in an instrument's
  `args` (the Dicon GP800 switch carries a hostname, username and password). This is what lets a
  reloaded queue rebind its own instruments rather than depending on the Experiment Wizard's last
  selection - but treat the file accordingly. You are warned when credentials are present.
- **"Refine stage calibration from Search-for-Peak results" does apply to queued `sfp` steps.** It is
  available even with the global "execute search for peak" switched off, which is the normal way to
  run a loaded queue - it only needs a Search for Peak to have been initialised. The refinement is
  attributed to the `device_id` on the `sfp` entry, or, when that is omitted, to the device of the
  preceding `move` entry. An `sfp` step that neither names a device nor follows a move cannot be
  attributed, so it logs a warning and skips refinement rather than guessing.
- The queue is appended to the existing ToDo list and appears in the ToDo table, where alignment steps
  show as "Move to device" / "Search for Peak". They can be reordered and deleted like any other entry,
  but not edited or cloned, since they have no measurement.
- If an alignment step fails, the experiment pauses and the entry stays at the head of the queue, the
  same way a failed measurement behaves.
